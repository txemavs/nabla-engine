# 21. Virtual and augmented reality

[Manual contents](README.md)

XR adapters connect immersive presentation and input to engine behavior. Public
modules include `@nabla/engine/xr`, `/xr/ui`, `/ar`, and specialized bow, hoop,
placement, and weapon adapters. Importing the AR entry does not itself instantiate
the demo. Device capability must be checked at runtime.

The reference `/headset.html` page selects VR/AR experiences. Use a secure, trusted
origin for remote devices and preserve the local HTTPS configuration. A headset
browser and a PC browser driving a headset have different performance and input
characteristics; they also have separate settings scopes.

## Sessions and input

`XRSessionController`, `GameXR`, and `XRGameInput` manage session and input integration.
Tracked hands, controller sources, grabbing, and calibration have dedicated modules.
Connect logical actions to existing gameplay state so that desktop and immersive
controls agree on inventory and vehicle behavior.

`inspectXRDevice` reports observable browser/input information. It does not reliably
identify every physical transport or guarantee a capability from a user-agent hint.
Handle missing hand tracking, denied access, and session termination as normal
integration cases.

## AR composition

AR modules expose room representation, scaled vehicles, touch control, and object
interaction. Their physical composition differs from simply enabling a transparent
background on a desktop world. Follow the relevant adapter's ownership contract;
do not assume all AR demos reuse every desktop session detail unchanged.

For a first device test, choose the test world, enter a session, calibrate, exercise
one interaction, exit, and re-enter. Then add geographic content or heavier assets.
Validate placement scale and contact behavior before tuning rendering quality.

Bow and hoop experiences have separate simulation modules and XR wrappers. The
experimental Betaflight path is explicitly experimental and should be documented
with its current limitations when included in an application.

## Verification limits

A desktop typecheck cannot validate stereo rendering, comfort, controller mappings,
passthrough, or frame timing. Record browser, device, session mode, quality, and
actual backend with any XR test result. Desktop FSR behavior does not imply the
same scaling path in immersive XR.
